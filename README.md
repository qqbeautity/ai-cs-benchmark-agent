# AI 客服竞品横评 Agent

输入 3–5 个 AI 客服产品，自动联网调研，生成带证据来源、对比矩阵与 AI 洞察的横评报告。

**项目状态：骨架完成，示例路径可演示，真实调研链路尚未验证。**

> 这份 README 是**项目现状说明**，不是成品宣传。最后更新：2026-09-14。
> 面向面试官的精简版和完整技术方案见文末的「相关文档」。

---

## 一、这个项目在解决什么问题

让大模型做竞品调研，最大的坑不是它写得不好，而是它**会自信地编造**：

- 编造一个根本不存在的价格
- 编造一个它"记得"的客户数量
- 最隐蔽的：编造一条**看起来有来源、实际查无此处**的引用

前两种容易被发现，第三种最难——报告里写着"已核实事实"、旁边挂着 `[S3]` 标签，读者点不开或者点开发现对不上，整份报告的可信度就塌了。

所以这个项目的核心不是"让 AI 写报告"，而是**让 AI 写的每一句话都可追溯，且这个可追溯是程序保证的，不是靠提示词祈祷的**。

## 三、怎么跑起来

```bash
npm install
npm run dev        # 默认 3000 端口
```

打开 http://localhost:3000 ，点首页的「**查看示例报告（无需 API Key）**」——**这条路径不发起任何联网请求**，可以立刻看到报告的完整形态。

### 想看真实调研？需要先配两个免费 Key

| 服务 | 申请地址 | 免费额度 |
|---|---|---|
| Tavily（联网搜索） | https://app.tavily.com/ | 1000 credits / 月 |
| 通义千问（结构化抽取） | https://bailian.console.aliyun.com/ | 新用户有免费额度，之后按量计费 |

两个都**不需要信用卡**。模型层走的是**任何 OpenAI 兼容端点**——想换回 Gemini、DeepSeek 或 Kimi，改 `.env.local` 里的 `LLM_BASE_URL` / `LLM_MODEL` 就行，代码不用动。

```bash
cp .env.example .env.local
# 编辑 .env.local 填入两个 Key
npm run dev
```

**只填 Key 还不够，`LLM_BASE_URL` 要照抄百炼控制台给你的那个地址。** 它可能长这样：

```
https://ws-<你的空间 ID>.cn-beijing.maas.aliyuncs.com/compatible-mode/v1
```

这是**工作空间专属域名**，和公开的 `dashscope.aliyuncs.com` 不是一回事。区域或空间对不上会报 `InvalidApiKey`，而那个报错看起来像 Key 本身有问题——所以别照着 `.env.example` 里的示例值猜。

**两个默认设置是有原因的，别顺手改掉：**

- `LLM_JSON_MODE=json_schema` —— `qwen3.8-max` 上实测生效（返回 200，content 严格符合 schema），不是被静默降级成 `json_object`
- `LLM_DISABLE_THINKING=1` —— Qwen3.8 系列**默认开着思考模式**，而推理 token 和正文一起计费、也一起受 `LLM_MAX_TOKENS` 约束。实测同一个问题：不关烧 50 个 token（38 个是推理），关掉只要 5 个。不关的话十维抽取（输出几千 token）很容易撞上截断

**额度换算**：一次完整演示（5 产品 × 3 次搜索）= 15 credits，1000 ÷ 15 ≈ **每月 66 次**。

> ⚠️ 模型服务商可能将输入用于改进产品。本项目只处理公开网页，**不要输入企业机密**。

## 四、技术方案一句话版

```
产品名 + 官网（可选）
        ↓
   Tavily 搜索（每产品最多 3 次，官网域名优先）
        ↓
   来源编号化 [S1] [S2] [S3] ...    ← 只有编号进模型，URL 不进
        ↓
   模型按十维结构化抽取（受 json_schema 约束，所有产品合并成 1 次调用）
        ↓
  ★ 程序校验：模型引用的 sourceId 真的存在吗？    ← 项目的核心
        ↓
   查无此引用 → 该条事实降级为「待确认」
        ↓
   热力矩阵 + 覆盖率图 + 定价表 + 三级证据标注
```

**为什么只让编号进模型？** 因为一旦 URL 进了上下文，模型就会开始"修饰"它——补全路径、改写成看起来更权威的域名。编号是它可以引用、但无法伪造的。

**校验规则**（`src/lib/schema.ts`，文案与降级说明在 `src/lib/types.ts`）：

- 引用了不存在的 sourceId → 降级为「待确认」，并在界面上说明**为什么**降级
- 某个维度声称有能力、但所有引用都失效 → 该维度**退回「未知」且摘要清空**（有摘要没证据 = 读起来像已确认事实）
- 模型写进正文的 URL → 一律替换成 `[链接见来源]`，页面只渲染我们亲自抓取并校验过的链接

## 五、十个分析维度

产品定位与目标客户 · 客服接入渠道 · AI Bot 与自动回复 · 知识库与 RAG · 人工接管与坐席辅助 · 工作流和自动化 · 数据分析 · 集成能力 · 安全与部署 · 定价及试用政策

每个维度四种状态，**同时带图标和文字**（不依赖颜色区分，色盲 / 灰度打印 / 强制配色模式下都可读）：

| 状态 | 图标 | 判定标准 |
|---|---|---|
| 支持 | ✓ | 摘录明确说明该能力存在 |
| 部分支持 | ◐ | 存在但有限制、需额外付费、或仅部分渠道 |
| 不支持 | ✕ | 明确不支持，或由第三方提供 |
| 未知 | ? | 摘录未提及或说法冲突 |

每条结论另带三级证据标注：**已核实事实**（可点开来源）/ **AI 推断**（跨事实归纳）/ **待确认**（资料不足或冲突）。

### 一个函数，两个调用方

产品卡片（优势 / 短板 / 适用用户 / 定价模式）由 `types.ts` 里的 `deriveProductInsights` **统一产出**。区别只在于传不传模型散文：服务端 `report.ts` 传模型归纳的结果，客户端在没有洞察时（降级、占位示例）不传，函数自己回退到从已验证事实里推导。

以前这里有两份实现——报告页复制过一份服务端定价推导，两边各自演化。现在只有一份，且它躺在客户端安全的模块里，所以两边都能用。

### 一条重要的结构规则

`src/lib/server-env.ts` 带 `import "server-only"`。**任何客户端组件都不许直接或间接引用它**——一旦引用，Next.js 会在**构建期**报错。

这不是洁癖。项目第一次跑起来时就是这么白屏的：`report/page.tsx` 从 `report.ts` 导入了一个叫 `isDone` 的类型守卫，而 `report.ts` 依赖 `server-env.ts`，结果整个服务端模块被拖进浏览器包，模块顶层守卫抛错，报告页整页崩溃。

修复方式是把 `isDone` 挪到 `types.ts`（它本来就是个纯类型守卫）。**如果客户端要用服务端模块里的东西，把它挪到 `types.ts`，而不是放宽边界。**

## 七、命令

```bash
npm run dev            # 开发服务器（3000 端口）
npm run build          # 生产构建
npm run typecheck      # 类型检查
npm test               # 全部单元测试（48 个）
npx vitest run src/lib/schema.test.ts      # 只跑一个文件
npx vitest run -t "降级"                    # 按测试名跑单个用例

npm run smoke          # 三个浏览器冒烟脚本 + 截图
npm run fixture        # 用真实 API 生成示例报告（会拒绝覆盖占位数据，除非带 --force）
```

**注意事项：**

- `npm run smoke` 需要 dev server 跑在 **3111** 端口（`npx next dev -p 3111`），脚本里硬编码了这个端口
- 三个冒烟脚本：`smoke-home.mjs`（首页与表单校验）、`smoke.mjs`（占位报告，浅色+深色各一遍，并扫描页面正文有无密钥泄露）、`smoke-live.mjs`（真实路径：种入任务记录并把洞察请求 stub 成模型不可用时的真实返回，验证洞察失败时报告依然降级渲染）
- **整套冒烟测试不消耗任何 API 额度**，配没配 Key 都一样
- 截图输出到 `docs/screenshots/`
- `npm run lint` **是坏的**，没有 ESLint 配置，用 `npm run typecheck` 代替
- 报告页是客户端组件，**`curl` 只能拿到 loading 态**，验证内容必须用 Playwright 冒烟测试

## 八、一些刻意的设计取舍

| 决策 | 原因 |
|---|---|
| 十维用**热力矩阵**而非分组柱状图 | 5 产品 × 10 维度 = 50 个比较项，柱状图完全不可读；而且这些是**状态值不是数值** |
| 定价用**表格**而非柱状图 | 多数厂商不公开可比价格，强行画图等于造假。只有当所有产品都有真实数字时才画图 |
| 洞察生成失败**不影响报告** | 矩阵和图表都基于已验证事实构建，洞察是可降级的附加层 |
| 调研**串行**而非并发 | 免费层限流下，429 风暴比慢一点更糟。这是有意设定的上限策略，不是"还没优化到的顺序代码" |
| 依赖只留 5 个 | 曾引入 `@tanstack/react-query`，但它只包了两个 `useState` 就能表达的请求。删掉后报告页首屏少 33 KB（gzip 后 10.8 KB） |
| 失败也返回 **HTTP 200** | 响应体是判别联合类型，前端要靠它渲染重试按钮。非 200 只表示请求本身格式错误 |
| 不建数据库 | 作品集 MVP，静态 fixture + localStorage 够用。完整报告不存 localStorage（5 产品×10 维度会超过 5MB 上限） |

### 部署说明

目标平台是 **Vercel**，不是 Netlify。

原因：单产品链路耗时 30–90 秒，而 **Netlify 的同步函数上限是 60 秒，且官方明确该限制不随套餐变化、不可配置**（升级付费也没用）。Vercel Hobby 在 Fluid Compute 下是 300 秒，足够。

部署前在 Vercel 项目设置里配置环境变量：`TAVILY_API_KEY`、`LLM_API_KEY`、`LLM_BASE_URL`、`LLM_MODEL`、`LLM_JSON_MODE`、`LLM_DISABLE_THINKING`，以及可选的 `LLM_MAX_TOKENS`。**`LLM_BASE_URL` 和 `LLM_MODEL` 在这里算必填**——代码里的兜底默认值指的是公开国内站，和你实际用的工作空间端点不是一回事。完整说明见 `.env.example`。
